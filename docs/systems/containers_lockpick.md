# Containers + Lockpick + Traps

**Scope.** Chest containers, the lockpick v3 flow, chest traps,
mimic springs, and the chest template loot pipeline. Lockpick v3
(2026-09-03) collapses picking to one economics question, binary
outcome; the trap table is driven entirely by `data/chest_traps.json`.

Source of truth: `src/container_system.py`, `src/items.py::Container`,
`data/items/container.json`, `data/chest_templates.json`,
`data/chest_traps.json`, `src/main.py::_lockpick`
(entry at `src/main.py:4548`).

---

## 1. One picture

```
Player bumps/adjacent chest + presses lockpick key
 └─ _lockpick()                              src/main.py:4548
      ├─ mimic? → _spawn_mimic + surprise 10-20% max_hp damage, return
      ├─ Solomonic Key passive? → bypass quiz, 1/floor, chain-3 loot
      └─ attempt_lockpick(player, container, ...)   src/container_system.py:83
           │
           │ ONE economics threshold-1 Q at container.quiz_tier
           ▼
         right  → _handle_success → full authored haul (3-4 items + bonus common
         wrong  → _handle_failure → trap fires at chest tier + maybe alert
                                     (no loot)
         both   → container.opened = True       (chest is the cost)
```

**Zero-tolerance applies.** One wrong answer = fail. There is no
retry — the chest itself is the cost.

**No durability.** Lockpicks (`src/items.py:968`) still carry historical
`durability_loss_success` / `durability_loss_failure` fields for loader
compatibility, but nothing in the live code reads them. Picks are a
flavor item + a quest grant.

## 2. Flow details

### Entry (`_lockpick`, `src/main.py:4548`)

Preconditions in order:

1. **Find adjacent container.** `_find_adjacent_container()` picks a
   `Container` in a 1-tile radius. None → "There is no container to
   pick nearby."
2. **Mimic springs out.** If `container.is_mimic`, `_spawn_mimic`
   (`src/container_system.py:489`) replaces the chest with a
   level-appropriate mimic monster:
   - `dungeon_level >= 80` → `abyssal_mimic`
   - `>= 60` → `gilded_mimic`
   - `>= 45` → `lurking_horror`
   - `>= 25` → `greater_mimic`
   - otherwise → `mimic`

   Surprise damage: `uniform(0.10, 0.20) * player.max_hp`. The chest
   is removed from `ground_items`, the mimic is appended to
   `monsters`, `monster_hit` plays, and the turn advances.
3. **Solomonic Key** (`chain_passives.consume_passive_charge(player,
   'solomonic_key')`) — Ring of Solomon T5 passive, 1/floor: bypass
   the quiz, open the chest at chain-3 quality. Full loot generated by
   `_handle_success` with `chain=3`.
4. **Normal path.** `attempt_lockpick(player, container, quiz_engine,
   dungeon, monsters, on_complete)` kicks off the economics quiz.

### The quiz

```python
quiz_engine.start_quiz(
    mode='threshold',
    subject='economics',
    tier=max(1, int(container.quiz_tier or 1)),
    callback=_callback,
    threshold=1,
    total_qs=1,
    wisdom=player.WIS,
    timer_modifier=player.get_quiz_timer_modifier(),
    extra_seconds=player.get_quiz_extra_seconds('economics'),
    base_seconds=player.get_quiz_timer('economics'),
)
```

### Success (`_handle_success`, `src/container_system.py:122`)

- `container.opened = True`
- Gold: rolls at the **top of the range** (0.70 lo .. gmax inclusive)
  because you did it right.
- Loot: `_generate_loot_from_template(container, dungeon.level)` returns
  3–4 real slots + 1 bonus common + rare_chance × 2 (unique roll).
- Messages: "The lock yields! You crack the chest." + per-item + gold.
- Callback receives `{status: 'opened', loot, gold, messages}`.

### Failure (`_handle_failure`, `src/container_system.py:149`)

- `container.opened = True` — no retry. The chest *is* the cost.
- Trap fires via `pick_trap_for_chest(container)` keyed to the chest's
  own tier (NOT the floor tier; this was a bug pre-v2.6.6 where a T1
  chest at floor 50 got a T3 trap).
- `_trigger_trap` applies damage + optional status effect.
- 30% chance to alert nearby monsters within 8 tiles
  (`_alert_nearby`). Sessile monsters flip to `aggressive`.
- No loot, no gold. Message: "You fumble the lock — the chest snaps
  shut."

### Caller glue (`src/main.py:4609`)

`_lockpick.on_complete` iterates `result['messages']`, drops loot onto
the chest's tile, deposits gold via `add_gold_to_tile`, and reports to
the quirk system:

- success → `quirk_system.on_lockpick_success()`
- failure → `quirk_system.on_lockpick_fail(container.id, dungeon_level)`
  + `quirk_system.on_trap_triggered(trap_type)` where `trap_type` is
  reverse-looked-up from the trap's flavor message (Job's Endurance
  wants distinct trap *types*; a static `'chest_fail'` collapses them
  all).

Fragile loot bash-damage: a shattered potion/scroll in a bashed chest
is reported as wreckage and dropped.

## 3. Container schema (`data/items/container.json`)

Post-v2.18.0 cleanup. Pre-v2.18.0 containers carried decoration blocks
(`"trap": {"type": "needle", "damage": "1d4", ...}`, `"trapped":
true`, `"quiz_threshold": 2`, `"extra_item_chance": 0.40`) that were
never read — all real trap data comes from `chest_traps.json`. Those
fields were removed in the v2.18.0 cleanup pass.

Current authoritative shape:

```json
{
  "wooden_chest": {
    "name": "wooden chest",
    "symbol": "&", "color": [139, 90, 43],
    "weight": 20.0, "min_level": 1,
    "tier": 1,
    "frequency": 10,
    "gold": [5, 25]
  },
  "iron_chest": {
    "name": "iron chest",
    "symbol": "&", "color": [160, 160, 175],
    "weight": 30.0, "min_level": 20,
    "tier": 2, "frequency": 8,
    "gold": [20, 60]
  },
  "steel_vault": {
    "name": "steel vault",
    "symbol": "&", "color": [100, 160, 210],
    "weight": 50.0, "min_level": 40,
    "tier": 3, "frequency": 6,
    "gold": [50, 120]
  },
  "enchanted_coffer": {
    "name": "enchanted coffer",
    "symbol": "&", "color": [180, 100, 230],
    "weight": 15.0, "min_level": 60,
    "tier": 4, "frequency": 4,
    "gold": [120, 250]
  },
  "dragon_hoard": {
    "name": "dragon hoard",
    "symbol": "&", "color": [255, 200, 30],
    "weight": 80.0, "min_level": 80,
    "tier": 5, "frequency": 3,
    "gold": [300, 800]
  }
}
```

### Fields

| Field | Purpose |
|-------|---------|
| `tier` (int, 1-5) | Severity gate. Drives `quiz_tier` default, trap tier, and the chest template bucket chosen at spawn time. |
| `quiz_tier` (int, defaults to `tier`) | Economics-quiz difficulty. |
| `gold` / `gold_range` (`[min, max]`) | Gold pool. Success rolls `[gmin + 0.7 * (gmax - gmin), gmax]`. |
| `frequency` (int) | Weight into the floor's container pool (`dungeon.pick_container`). |
| `min_level` (int) | Earliest floor the chest can spawn. |
| `template_id` (str, set at spawn) | Links to a `chest_templates.json` entry for the loot table. Not authored in `container.json`; stamped by `dungeon.pick_container()`. |

Runtime state set after instantiation:
- `opened: bool` — true after one successful (or failed) attempt.
- `is_mimic: bool` — true for chests chosen to be mimics.
- `_gold_bonus_accum` — scratch for `gold_bonus` loot-table hits.

### Removed/dead fields

Deprecated by v2.18.0 — safe to delete from any custom JSON:

- `trap` — decoration block, dead code since v2.6.6.
- `trapped` — flag, dead code since v2.6.6.
- `quiz_threshold` — was 2 everywhere; v3 forces threshold = 1.
- `extra_item_chance` — unused (replaced by `rare_chance_chain3`).

## 4. Chest templates (`data/chest_templates.json`)

Twelve named chest archetypes with thematic loot tables. Loaded by
`load_chest_templates()` (`src/items.py:1362`). The dungeon picks a
template by floor band at spawn, stamps `template_id` on the
`Container`, and the loot generator reads the template at open time.

Example:

```json
{
  "wooden_chest": {
    "id": "wooden_chest",
    "name": "wooden chest",
    "symbol": "&", "color": [120, 80, 40],
    "lore": "A simple traveler's box. Iron hasp, water-stained planks.",
    "tier": 1,
    "quiz_tier": 1,
    "gold_range": [5, 25],
    "trap_chance": 0.10,
    "loot_table": {
      "weapon_common": 25,
      "armor_common": 25,
      "shield_common": 10,
      "potion": 20,
      "ammo": 10,
      "scroll": 10
    },
    "rare_chance_chain3": 0.01,
    "spawn_weight_by_band": {
      "L1_15": 60, "L16_30": 30, "L31_50": 0,
      "L51_70": 0, "L71_90": 0, "L91_100": 0
    }
  }
}
```

### Template fields

| Field | Purpose |
|-------|---------|
| `tier`, `quiz_tier` | Mirror the Container fields. |
| `gold_range` | `[min, max]`. |
| `loot_table` | Category → weight dict. Categories map to item pools (`_COMMON_CATEGORIES`, `src/container_system.py:211`): `potion`, `scroll`, `wand`, `spellbook`, `accessory`, `ammo`, `ingredient`, `artifact`, `magic` (= wand+scroll+spellbook), `gear` (= weapon+armor+shield), or the explicit `weapon_common` / `armor_common` / `shield_common`. The pseudo-category `gold_bonus` adds extra gold instead of pulling an item. |
| `rare_chance_chain3` | Baseline chance that the chest contains a unique. The success handler multiplies this by `FULL_RARE_MULT = 2.0` (`src/container_system.py:42`) to match the pre-v2.6.6 chain-5 "Master Thief" tier. |
| `spawn_weight_by_band` | Per 15-floor band weights for `dungeon.pick_container`. |
| `pre_identified` (optional) | `merchant_strongbox` sets `true`; all loot comes out fully identified. |

### Loot generation (`_generate_loot_from_template`, `src/container_system.py:395`)

```python
level_cap   = dungeon_level + chest.tier * 2
n_items     = randint(3, 4)
bonus_slots = 1
eff_rare    = min(1.0, base_rare * 2.0)
rare_slot_index = randrange(n_items) if (unique_pool and random() < eff_rare) else -1

for i in range(n_items):
    if i == rare_slot_index:
        it = draw_unique() or draw_common()
    else:
        it = draw_common()
    append

for _ in range(bonus_slots):
    append(draw_common())
```

**Common gear** is template+material rolled at draw time via
`pick_random_weapon_for_floor` / `pick_random_armor_for_floor` /
`pick_random_shield_for_floor` — chest loot is NOT drawn from a static
`weapon.json` pool.

**Ingredient hygiene.** Only `tier_role == 'dungeon'` ingredients
(terrain-foraged: cave mushroom, swamp moss) are eligible for chest
loot. Monster-derived cuts (`family` / `prime` / `trophy`) come **only**
from harvest. Enforced in both `_build_common_pool` and
`_build_unique_pool`.

**Pre-identified chests** (`pre_identified: true` in template) stamp
`identified = True`, `id_level = 5`, `buc_known = True` on every item
in the haul — merchant strongbox gift.

## 5. Trap table (`data/chest_traps.json`)

Introduced v2.6.6. Keyed by tier, 4–5 variants per tier. Every failed
chest pick fires one random trap from the chest's own tier (not the
floor tier — pre-v2.6.6 bug).

### Shape

```json
{
  "_meta": {"version": "v2.6.6", "description": "..."},
  "traps_by_tier": {
    "1": [
      {"type": "needle", "damage": "1d4", "effect": "poisoned",  "effect_duration": 5, "message": "A poisoned needle springs from the lock!"},
      ...
    ],
    "2": [...],
    "3": [...],
    "4": [...],
    "5": [...]
  }
}
```

Each entry:
- `type` — identifier (fed to `quirk_system.on_trap_triggered`).
- `damage` — dice string (`"1d4"`, `"2d6"`, `"5d6"`), rolled with
  `dice.roll`.
- `effect` — canonical status effect id (empty = no debuff).
- `effect_duration` — turns, with jitter via `dice.roll_duration`.
- `message` — flavor text printed on fire.

### Tier severity ladder

| Tier | Damage | Example effects | Lethality |
|------|--------|-----------------|-----------|
| 1 | 1d3 – 1d6 | poisoned 5, bleeding 4, confused 3 | small nick |
| 2 | 1d4 – 2d4 | stunned 4, confused 6, corroding 4, sleeping 3 | hurts but survivable |
| 3 | 1d8 – 3d4 | stunned 5, slowed 6, burning 4, bleeding 6, cursed 20 | real cost |
| 4 | 1d6 – 3d6 | confused 8, blinded 5, draining 6, cursed 30, silenced 8 | can end a bad run |
| 5 | 2d8 – 5d6 | blinded 6, paralyzed 4, petrifying 5, immobilized 5, burning 6 | lethal if you were already hurt |

### Trap-pool loader

```python
def _load_trap_pool() -> dict[int, list[dict]]:
    """Load traps_by_tier from data/chest_traps.json. Cached."""
```

(`src/container_system.py:52`). Caches `_TRAP_POOL_CACHE` on first
read. `pick_trap_for_chest(container)` clamps tier to `[1, 5]` and
returns a random dict; empty on no pool.

### Trap fire path (`_trigger_trap`)

```python
dmg_roll = trap.get('damage', '0')
raw_dmg  = roll(dmg_roll) if dmg_roll != '0' else 0
actual   = player.take_damage(raw_dmg, 'physical') if raw_dmg else 0
# message: trap.message
# "You take N damage!" if actual > 0

effect     = trap.get('effect')
effect_dur = roll_duration(trap.get('effect_duration', 5))
if effect:
    applied = player.add_effect(effect, effect_dur)
    # "You are {effect}!" or "You resist the {effect} effect!"
```

Damage goes through `player.take_damage(dmg, 'physical')`, so armor DR
and immunity statuses apply as usual. The debuff goes through
`add_effect`, so saving-throw guards apply where categorized.

## 6. Mimic springs

A fraction of containers on the floor are flagged `is_mimic = True` by
dungeon spawn code (frequency controlled per floor). When the kid tries
to pick one, `_spawn_mimic` runs:

- Replace the Container on the tile with a Monster instance
  (`src/container_system.py:489`).
- Pick the mimic variant by `dungeon_level` band (see §2.2).
- Surprise damage lands immediately: `uniform(0.10, 0.20) *
  player.max_hp`, floored at 1 and never below HP 1 (survival-floor
  rule — the mimic can't be the thing that kills you outright).
- The turn advances once; the mimic takes its first AI turn next.

The spawning function loads the full `data/monsters.json` definitions
and falls back to the base `mimic` if a tier-specific variant is
missing.

## 7. Historical notes

### Pre-v2.6.6 (chain-tier lockpick)

The old flow ran an escalator-chain economics quiz; chain reached
scaled loot and gold:
- Chain 0 → empty chest + maybe trap at floor tier.
- Chain 3 → modest loot ("Journeyman").
- Chain 5 → full authored haul + bonus item ("Master Thief").

v2.6.6 (2026-09-03) collapsed this to one question for consistency
with harvest (one animal Q), cook (one cooking Q), and identify (one
philosophy Q). Memory `feedback_flow_over_gradient.md` has the
rationale: high-freq quiz-gated actions get ONE question and the
reward for playing well is the GAME FLOWING, not tier-scaled loot.
Chain mode stays for low-freq high-stakes attempts (pray, boss, mythic
scroll).

### v2.18.0 cleanup

- Deleted `trap` and `trapped` decoration blocks from
  `data/items/container.json`.
- Dropped `quiz_threshold` and `extra_item_chance` from the schema.
- Kept only `tier`, `quiz_tier`, `frequency`, `gold`/`gold_range`,
  `min_level`, `weight`, display fields, and runtime fields set at
  spawn.
- Removed four unused lockpick variants (`mithril_lockpick`,
  `diamond_lockpick`, `philosophers_pick`, plus the name-mismatch on
  `_new_game`'s basic lockpick grant).
- `_lookup_trap_type` (`src/main.py:4654`) reverse-maps the trap
  flavor message back to the `type` id so Job's Endurance registers
  distinct traps.

### Known quirks (per SYSTEMS_AUDIT.md)

- `mystery_system.py::_run_cooking_challenge` still runs an
  `escalator_chain` cooking quiz with threshold=5 for the Cauldron
  mystery, which violates the v3 one-Q rule everywhere else. Noted
  but not fixed in v2.18.0.
- `main.py:4544` (older line) — success/fail detection historically
  used `bool(result['loot']) or gold > 0`. The current code reads the
  `success` message tag from `result['messages']` instead, which is
  the canonical signal.
